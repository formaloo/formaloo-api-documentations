# AC contract fact migration

Inventory for the source-first move from MCP custom-UI prose into the published HTTP contract. Schema stays in formz. This repo adds only guidance the schema cannot express. `primary_form` is unchanged.

A search miss is not a permanent unsupported claim. `GET /v3.0/dashboard-search/` searches boards, folders, and forms. Form and row list views set `search_fields` (`formz/rest/views/admin/v5/forms.py`). Re-check the operation before calling a capability unsupported.

Generated descriptions inline `spec/docs/v3.0/**` when the service spec `$ref`s that file. Public and MCP formz bundles share those paths (`scripts/fetch-specs.mjs` rewrites `docs/mcp-1.0/` to `docs/v3.0/`). `spec/v3.0.yaml` also inlines `spec/docs/v3.0/intro.md` as the public info description. No new operation IDs and no docs-owned schema patch.

## Source-contract defects

These are backend or cross-service gaps. This repo does not patch the schema.

1. Alias submit and submit-time logic disagree. `submit_by_alias` stores answers, but `LogicService` evaluates the raw body by slug first. Emails, PDFs, Slack, webhooks, and `jump_to_success_page` do not see alias-keyed answers. Fix in formz by resolving aliases before logic, if alias submit is supposed to drive those actions.

## Alignment to verify

Hosted ending-page polling uses `GET /v1/custom-prompt-results/{slug}/` on the configured AI base URL (`AIService`, default `https://ai-api.formaloo.me`). This reference documents `GET /v3.0/custom-prompt-results/{slug}/` and `spec/ai.yaml` does not declare a server. Both paths may be valid versioned routes. That is not recorded here as a proven backend defect. Confirm against the AI service before changing either client or the published path.

File answers use `StoredFileField` when `request.version` is at least `v3.2` (`SubmitRowSerializer.get_serialized_field` in `formz/rest/serializers/v5/forms.py`). `URLPathVersioning` takes the first path segment (`idealib/api/versioning.py`). Live routes are `path("v5/", ...)` in `formz/urls/published_versions/__init__.py`. Public OpenAPI paths are `/v3.0/` because `SCHEMA_PATH_PREFIX_INSERT` is `v3.0`. The service-local `proxy/default.conf` forwards `/` with no path rewrite. That file is not the public gateway, and the gateway config was not available, so it does not show whether a public `/v3.0/` submit is rewritten before version detection. This is an unresolved deployment alignment check, not a proven public API restriction. Public Files and Submit pages state only that the hosted client uploads first and submits the returned slug, and that custom integrations must verify stored-file submission support against the deployed submit API. They do not promise slug acceptance and do not claim slug rejection.

Chart and form-display `subtype` is already `read_only=True` on the formz serializers. Schema already owns it. No docs schema override.
